# Support

Gitrune is early alpha software maintained on a best-effort basis.

Before requesting help:

1. Read the [README](README.md), especially requirements and verification.
2. Confirm that `git --version`, `node --version`, `npm --version`, and `rustc --version` run successfully when developing from source.
3. Search existing GitHub issues.
4. Reproduce the problem with the latest build when it is safe to do so.

Open a GitHub issue for reproducible bugs or focused feature proposals. Include Gitrune version, Windows version, Git version, repository state, expected behavior, actual behavior, and sanitized reproduction steps. Never include credentials, private keys, confidential repository contents, or unredacted logs.

Use the private process in [SECURITY.md](SECURITY.md) for vulnerabilities. General Git training, recovery of damaged third-party repositories, and provider account support are outside the project's support scope.
