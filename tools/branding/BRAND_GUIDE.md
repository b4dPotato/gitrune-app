# Gitrune brand kit

The approved G-shaped commit graph represents local repository history, branches, and merges. All shipping variants are mechanically traced from the approved original. The original raster is preserved in `master/approved-original.png`; SVG exports normalize its slightly textured colors into solid fills and remove isolated raster speckles. The SVGs contain real vector paths, not embedded PNGs. Wordmarks use outlined Inter SemiBold, so no font installation is needed to display them.

## What to use

| Surface | Delivered formats and dimensions | Location |
| --- | --- | --- |

These are a practical cross-platform set, not a claim that every listed size is mandatory. A showcase website primarily needs its wordmark, favicon, Apple touch icon, and share image. The manifest and maskable icons are supplied for future use; this kit does not implement a PWA or browser-based Git client. The manifest uses `display: browser` deliberately.

## Colors and placement

- Primary teal: `#34c0a2`.
- Dark tile / ink: `#0e1216`.
- Pale commit nodes: `#caffeb`.
- Accessible darker teal for light surfaces: `#087f6d`.
- Light wordmark: `#f4faf8`.

Use `on-dark` on charcoal or similarly dark surfaces, and `on-light` on white/light surfaces. The light-surface mark has dark node centers to keep the graph readable. Black/white monochrome variants use transparent node centers so the three nodes remain visible in a single color.

Maintain aspect ratio. Give the mark clear space of roughly one node diameter. Prefer the horizontal wordmark at 150 CSS px wide or larger. Use the standalone mark for narrow navigation, browser tabs, and small controls. The browser favicon intentionally omits the tile to use the available pixels; the desktop icon retains the approved tile and original proportions. Prefer 24 px or larger when you control the display size; 16 px exports serve system UI constraints and naturally lose some graph detail.

The opaque touch icon lets the OS apply its own corner mask. The maskable variants keep the complete mark inside the central circle of radius 40% of image width; do not replace them with ordinary icons in the manifest.

## Desktop integration

The project uses a separate `src-tauri/icons/brand-v1/` set and points `bundle.icon` at it. Previous icon files remain intact. PNGs are 8-bit RGBA. The ICNS is generated by the project's installed Tauri CLI. The Windows ICO contains PNG-compressed RGBA frames and keeps 32 px first, following Tauri guidance.

For a manually packaged Linux app, install the included `hicolor` tree under the distribution's shared icons directory, normally `/usr/share/icons/hicolor/`, and set `Icon=gitrune` in the desktop entry. The executable path, desktop entry, icon-cache update, and package ownership belong to packaging and are not supplied as a fake launchable application. For Tauri bundling, use the configured PNG icon list.

The macOS `.icns` is the ready-to-use Tauri artifact. The `.iconset` can also be compiled on a Mac with:

```sh
iconutil -c icns Gitrune.iconset -o icon.icns
```

Apple's newer layered workflow uses Icon Composer. Import the separate foreground/background files if adopting it, then save and validate a `.icon` document on a Mac. These files are prepared inputs, not a completed or validated Icon Composer project. Don't add an extra rounded square to the Composer background. The standard `.icns` remains the compatible path supplied for this Tauri application. App Store listing screenshots and final platform-specific submission checks depend on the chosen release channel.

Tray assets are optional: the app has no tray behavior wired by this kit. On macOS, set the tray image's template flag when using the black template. Choose black/white variants appropriately on other desktops; do not use the filled rounded-square icon as a monochrome tray mask.

## Showcase website integration

Copy `website/` to your site's public `/brand/` directory. Use `horizontal-on-dark.svg` or `horizontal-on-light.svg` in the header. `head-snippet.html` contains links and social metadata. Replace `https://YOUR-DOMAIN.example` with the real deployment origin before publishing; Open Graph image URLs should be absolute. Adjust the manifest's start URL and scope if the site lives under a subpath. The current application receives only favicon/touch-icon links, not a fictitious showcase page or deployment URL.

SVG is preferred for logos; PNG is appropriate for share images and platform icon slots that require it. The two social card dimensions are practical export choices, not universal platform requirements. They describe the existing local-first client and do not claim that Linux/macOS releases are already available.

Example header:

```html
<img src="/brand/horizontal-on-light.svg" alt="Gitrune" width="150" height="40">
```

If a logo is inside a link already named by visible text, use an empty `alt` to avoid duplicate announcements. Website screenshots, release downloads, and product copy are separate launch assets, not logo variants.

## Regeneration and validation

From the project root:

```sh
npm ci --prefix tools/branding
node tools/branding/generate.mjs
node tools/branding/verify.mjs
node tools/branding/integrate.mjs
```

The exporter reads `docs/branding/gitrune-logo.png`, traces its tile, teal route, and pale node centers, outlines the wordmark, and creates all deliverables in `docs/branding/kit/`. The 2048 px PNGs are rendered from vector paths, not enlarged raster exports. Package versions are locked under `tools/branding/`; these are isolated asset-production dependencies, not runtime application dependencies. The integration script copies generated platform files into `src-tauri/icons/brand-v1/` and website assets into `public/brand/`.

`asset-manifest.json` records filenames, sizes, and dimensions. `preview.png` shows logo variants and small desktop sizes. File structure, actual dimensions, alpha channels, ICO/ICNS containers, and manifest references are checked locally. A Windows machine cannot establish final Dock, Finder, Linux shell, or App Store presentation; verify those in the target OS before release. This work prepares branding and icon wiring; it does not port, sign, notarize, or publish the application.

The original concept and the exploratory background-removal image were generated with the built-in image generation tool. The latter changed contours and was not selected for shipping; final geometry is traced from the approved original. The concept prompt is included at `master/concept-prompt.md`. No per-size generative redraws were used, keeping all exports consistent. Monochrome node outlines are expanded to remain visible when their centers become transparent.
